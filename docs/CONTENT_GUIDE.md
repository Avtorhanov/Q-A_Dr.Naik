# Откуда брать дополнения: источники, правила и план

Памятка для того, кто пополняет базу вопросов. Состояние на 26.11.2026: в базе 433 вопроса, вручную не сверен ни один.

## 1. Пять правил, которые нельзя нарушать

1. **Ничего не сочиняем.** Приложение показывает только существующий ответ Закира Найка. Ответ нельзя пересказывать, сокращать «своими словами» или дополнять.
2. **Всегда источник.** У каждой записи есть название выступления, дата (если известна) и рабочая ссылка. Для видео и аудио желательно указать минуту, где звучит вопрос.
3. **Нет ответа — так и говорим.** «Прямого ответа нет, вот самые близкие вопросы» или «В базе нет ответа». Порог не понижаем ради красивой выдачи.
4. **Модель не дообучаем.** Поиск сравнивает вопрос с вопросами в базе. Языковая модель может помогать понять вопрос или перевести интерфейс, но текст ответа она не формирует.
5. **Права.** Материалы принадлежат правообладателям (IRF, Peace TV и другим). Пока нет письменного разрешения, тексты ответов в репозиторий не попадают. Внутри приложения играет запись с сайта источника, сама запись не скачивается и не хранится.

## 3. Откуда не брать

- **Пересказы и конспекты.** Сайты с «кратким содержанием видео», статьи «Закир Найк сказал, что…», ответы чат-ботов. Это уже не его слова.
- **Автоматические расшифровки как текст ответа.** В них путаются имена, цифры и ссылки на аяты. Годятся только для поиска места в записи.
- **Нарезки и ролики с монтажом,** где ответ обрезан или склеен из разных выступлений.
- **Заголовки-приманки как формулировка вопроса.** «ОНА ПРИНЯЛА ИСЛАМ!» — это не вопрос. Вопрос выписываем из самой записи, заголовок оставляем в поле `question_original`.
- **Чат-боты, изображающие Закира Найка.**
- **Перезаливы без указания первоисточника,** если есть оригинал. Если оригинала нет, берём перезалив и пишем об этом в `note_ru`.

Отдельно, до ручной проверки не берём:

- вопросы о конкретных терактах, войнах и политиках. В версии 1 по этой причине пропущены вопросы о достоверности новостей и о событиях 11 сентября, в версии 2 — вопросы о взрывах смертников и об убийствах мусульман в мире;
- записи, которые могут входить в Федеральный список экстремистских материалов Минюста России. Список нужно проверить вручную до любой публичной публикации: автоматически он не читается;
- имена и личные данные людей из зала. Пишем «вопрос индуиста», «вопрос студентки», без имён.

## 4. Как добавить запись

Формат записи описан в [DATA_SCHEMA.md](DATA_SCHEMA.md). Коротко, на примере ролика:

```json
{
  "id": "qa_0233",
  "question_ru": "Вопрос по-русски",
  "question_en": "The question in English",
  "question_original": "Название ролика или вопрос так, как он прозвучал",
  "question_lang": "ru",
  "answer_text": null,
  "answer_lang": "ru",
  "source": {
    "type": "video",
    "title": "Название ролика",
    "publisher": "Призыв Dawah (YouTube)",
    "url": "https://www.youtube.com/watch?v=XXXXXXXXXXX",
    "timecode": null,
    "url_at_time": null,
    "date": "2024",
    "date_kind": "upload"
  },
  "topics": ["god"],
  "keywords": ["слова", "которых", "нет", "в", "вопросе"],
  "rights": "pending",
  "verified": false
}
```

По шагам, можно с телефона:

1. Откройте в репозитории файл `data/qa.json` и нажмите на карандаш («Edit»).
2. Прокрутите в самый конец. Перед последней скобкой `]` поставьте запятую после предыдущей записи и вставьте новый блок.
3. Номер `id` — следующий по порядку.
4. `answer_text` всегда `null`, `rights` — `pending`, `verified` — `false`.
5. Отдельным коммитом откройте `app.js` и в самом начале поменяйте дату `dataVersion: "ГГГГ-ММ-ДД"` на сегодняшнюю. Эта дата видна в шапке приложения как «Обновлено …». Ту же дату можно поставить в `index.html` (строка с `id="upd"`): это запасной текст, проверка базы напомнит, если даты разошлись.
6. Откройте `sw.js` и поменяйте дату в имени кэша (`qa-v2-ГГГГ-ММ-ДД`): так установленное на телефон приложение быстрее получит новую базу.
7. Нажмите «Commit changes». Через несколько минут GitHub сам проверит базу и соберёт новый APK. Если в базе ошибка, сборка остановится, а во вкладке «Actions» будет написано, в какой записи дело.

Правила разметки:

- Один вопрос — одна запись. Два вопроса в одном ролике — две записи с одной ссылкой.
- Повтор вопроса из другого выступления сохраняем отдельной записью: пользователь увидит оба ответа.
- Та же запись на другой площадке (аудио вместо видео, копия на Rutube) — это не новая запись, а строка в `also`.
- Утверждение из зала помечаем «(утверждение из зала)», вопрос на урду — «(на урду)».
- Дата — дата выступления. Если известна только дата публикации ролика, ставим `"date_kind": "upload"`.
- `keywords` — синонимы и слова, которых нет в самом вопросе: «ураза» к вопросу про пост, «кредит» к вопросу про проценты.

## 5. Чтобы ответ играл прямо в приложении

| Что в записи | Что видит пользователь |
|---|---|
| Ссылка на YouTube, Rutube или OK | Кнопка «Смотреть здесь». Плеер открывается в карточке |
| Плюс `timecode` (`"01:51:20"`) и `url_at_time` | Запись начинается с минуты, где задан вопрос |
| `media_url` — прямая ссылка на файл `.mp3`, `.m4a` или `.mp4` (только `https://`) | Кнопка «Слушать здесь» или «Смотреть здесь», плеер с выбором скорости |
| Ничего из этого | Кнопка «в источнике»: страница откроется в браузере |

Сейчас внутри приложения играют 83 записи из 433: все ролики YouTube, Rutube и OK. Точный таймкод есть у 19. Плеер работает на сайте и в Android-приложении. Если его нужно убрать совсем, поставьте `player: false` в блоке `FEATURES` файла `app.js`: останутся только ссылки на источник.

Про аудио Muslim Central. Лента подкаста закрыта для автоматического чтения, поэтому прямых ссылок на файлы в базе пока нет, и эти записи открываются на странице источника. Прямую ссылку можно вписать вручную: откройте страницу выпуска, найдите кнопку скачивания, скопируйте её адрес в `media_url`. Перед массовым добавлением лучше спросить у Muslim Central, не против ли они, что файл проигрывается с их сервера внутри стороннего приложения.

Таймкод для полной сессии: откройте запись, найдите момент, где начинается вопрос, запишите время как `ЧЧ:ММ:СС`. Для YouTube `url_at_time` — это ссылка с `&t=…s` в конце, где число — время в секундах. Проверка базы сверяет одно с другим.

## 6. Как сверять запись (`verified: true`)

Ставим `true` только после того, как человек открыл источник и убедился, что:

1. ссылка открывается и ведёт на нужную запись;
2. отвечает действительно Закир Найк, а не другой лектор;
3. вопрос в базе совпадает по смыслу с вопросом в записи;
4. таймкод попадает на начало вопроса (допуск — несколько секунд);
5. название, площадка и дата указаны верно;
6. для книги — номер страницы, для текста сессии — номер вопроса;
7. запись не относится к темам из раздела 3.

С чего начать: 20 вопросов книги и 19 вопросов сессии в Дохе. Их легко проверить, и после этого на главной странице перестанет стоять «сверено: 0».

## 7. Тексты ответов

- В репозитории текстов нет и быть не должно, пока `rights` равно `pending`. Проверка базы не пропустит запись с текстом и `pending`.
- Сейчас показ текста выключен целиком. В начале файла `app.js` есть блок `FEATURES` с двумя выключателями: `player` (встроенный плеер, включён) и `reader` (текст ответа, выключен). Код читалки остался на месте: чтобы вернуть её, замените `reader: false` на `reader: true`.
- Для внутреннего теста тексты кладутся в отдельный файл `private_texts.json` вида `{"qa_0001": "текст ответа"}`. При включённой читалке он загружается в разделе «О проекте», хранится только на устройстве и записан в `.gitignore`.
- После письменного разрешения правообладателя: включается `reader`, текст переносится в `answer_text`, `rights` меняется на `granted`. Тогда в карточке появляется кнопка «Читать здесь», а под текстом всегда стоит строка с источником и ссылкой.
- Текст — только дословный, из расшифровки, сверенной с записью.

## 8. Рекомендации на будущее

**Ближайшее**

1. Сверить вручную первые 40–50 записей (раздел 6).
2. Написать в IRF и Peace TV: запросить разрешение на тексты и, если получится, готовые расшифровки. Шаблона письма (в брифе он назван «файл 07») в проекте нет, его нужно составить.
3. Проверить Федеральный список экстремистских материалов и решить, каким будет репозиторий: открытым или закрытым.
4. Добавить оставшиеся ролики «Призыв Dawah».

**Поиск**

5. Заменить поиск по словам на поиск по смыслу (эмбеддинги, модели `multilingual-e5` или `bge-m3`). Для замены достаточно переписать файл `search.js`, сохранив функции `buildIndex()` и `search()`. Модель весит сотни мегабайт, для телефона это тяжело, поэтому вектор запроса удобнее считать на небольшом сервере, а поиск по словам оставить запасным вариантом без сети.
6. Пороги «найден ответ / близкие / нет ответа» подбирать заново на списке проверочных вопросов (`tests/search.test.js`). Правило прежнее: лучше честное «прямого ответа нет», чем чужой ответ.

**Данные**

7. Таймкоды для полных сессий размечать с помощью Whisper: он даёт расшифровку с временем, человек отмечает начало каждого вопроса. Расшифровка при этом остаётся рабочим материалом и в базу не идёт.
8. Раз в несколько месяцев проверять, что ссылки живы. Ролики удаляют, каналы закрывают.
9. Вести список «чего не нашли»: вопросы пользователей, на которые в базе нет ответа, подсказывают, что добавлять.

**Приложение**

10. Telegram-бот на той же базе и том же поиске.
11. Для магазина приложений нужен собственный ключ подписи и разрешение правообладателя. Демонстрационный ключ из репозитория для этого не годится.
12. Не добавлять в приложение счётчики, которые собирают вопросы пользователей без их ведома: вопросы о религии — личные данные.

## 9. Что в версии 2 не проверено

- Ни одна запись не сверена с источником вручную.
- У 34 новых записей Muslim Central вопрос взят из заголовка страницы или восстановлен по автоматической расшифровке. Там, где он восстановлен, в записи стоит пометка.
- Год у новых записей Muslim Central — это год публикации страницы по данным поисковика, а не год выступления.
- Темы шести выпусков серии про Рамадан взяты из описаний страниц, сами выпуски не прослушаны.
- Сборка APK и плеер внутри Android-приложения на телефоне не проверялись: APK собирается на GitHub после отправки кода.
